### Assistant governance

- Added the `/aid/assistant-governance` console for Runtime Agent versions, run traces, registered Tool contracts, budget authorizations and dynamic input traces. Run, budget and input detail reads remain audited and redact prompt or answer bodies from list views.
- Runtime Agent management uses the real `/aid/runtime-agent` APIs: create and edit identity, enable or disable, load/save/validate a draft, publish an immutable version, inspect version history, and activate or roll back with `expectedCurrentVersionId` compare-and-set protection.
- Draft publication freezes the full system instruction, `ASSISTANT_LOOP` / `assistant-loop/v1`, the selected enabled `text.chat` model, exact Skill version plus package digest, and exact Tool contract version plus schema digest. A published version is shown as runtime available only when the matching executor, model, Skill packages and Tool registrations are all currently available.
- Tool choices come only from the server-owned Java registry. The console has no uploaded-script or arbitrary execution entry. The read-only Tool catalog exposes the registered contract and operational properties under `aid:assistant:tool:query`.
- Runtime Agent permissions are `aid:assistant:agent:list`, `aid:assistant:agent:query`, `aid:assistant:agent:edit`, `aid:assistant:agent:publish`, and `aid:assistant:agent:activate`. Trace permissions remain separated as `aid:assistant:run:*`, `aid:assistant:tool:query`, `aid:assistant:budget:*`, and `aid:assistant:input:*`.
- Built-in Universal/Screenwriter resource import and module-default Agent binding do not yet have a completed management API in this unreleased build and are not reported as available.
