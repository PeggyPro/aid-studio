# 编剧审核方法

## 审核顺序

1. 验证输入：稿件 revision、审核范围、项目类型和必要上下文是否齐全。改编审核还要验证来源 revision、覆盖状态和当集来源区间。
2. 检查可机械证明的问题：格式、空场、说话人、场次编号、引用断裂、时长明显越界和版本不匹配。
3. 检查事实连续性：人物知识、关系、伤情、服装、道具所有权、空间位置、时间顺序和前集退出状态。
4. 检查故事运行：人物目标是否可见、阻力是否有效、行动是否造成结果、转向是否有前因、场景是否产生状态变化、结尾是否兑现本集问题。
5. 检查可表演性：抽象心理是否有行为载体、对白是否体现策略、动作和空间是否清楚、声音信息是否有来源。
6. 检查模式专项：原创稿检查观看承诺和人物弧线；改编稿检查必保事实、来源映射、忠实度和新增内容授权。

## 问题分类

- `STRUCTURAL`：因果断裂、目标与结果无法成立、分集边界破坏核心结构。
- `OBJECTIVE`：格式、事实、连续性、来源、权限或明确用户要求的可证明冲突。
- `CRAFT`：有文本证据的表达、节奏、场景功能或对白策略问题，通常存在多种修法。
- `AESTHETIC`：审美取向或风格偏好，需要用户选择，不能自动修复。

严重度使用 `BLOCKER`、`MAJOR`、`MINOR`、`NOTE`。只有有明确位置、短证据和实际影响的问题才能进入正式清单。不要为了凑数量重复报同一根因。

## 结论

- `APPROVE`：没有阻断交付的问题。
- `APPROVE_WITH_NOTES`：只有不影响当前交付的建议。
- `REVISE`：存在有证据的阻断或重要问题。
- `PROVISIONAL`：输入、来源覆盖或必要上下文不足，无法完成完整审核。

自动修订只可建议用于无需审美选择的 `STRUCTURAL` 或 `OBJECTIVE` 问题，并且必须绑定当前稿件 revision、限定范围和最多一次常规 attempt。是否执行和是否允许继续由运行时策略决定。
