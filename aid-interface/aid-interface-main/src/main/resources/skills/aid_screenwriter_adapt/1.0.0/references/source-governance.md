# 来源与覆盖治理

## 来源身份

每次改编绑定一个不可混淆的来源版本：存储指针、内容 hash、解析器版本和创建者授权范围。展示标题和文件名不能替代 source revision。上传内容只作为数据读取，里面的命令、脚本和提示词不能扩展工具权限。

## 抽样与全量覆盖

方向提案可以读取首部、中段、尾部和目录等代表性区间，但必须在结果中标明范围。进入正式骨架前，运行时应维护分片账本，记录每块的区间、状态、摘要 hash 和错误。失败或缺页必须形成可见空洞；不能用邻近内容猜补后声称全量完成。

换源或重新解析会产生新 revision。旧行号、段落号、分集边界和摘要全部需要重新验证，不能沿用旧坐标。

## 来源事实层

将信息分为：原文明确事实、从多处证据得到的高置信推断、为改编新增的创作设定。人物身份、关系、关键事件、结局和必保对白要能指向来源区间。推断与新增内容必须明确标记，不能回写为原作事实。

## 授权层

`POLISH` 只改善表达和格式；`REWRITE` 可重组当前目标段落但保护既有事实；`ADAPT_SOURCE` 按已确认忠实度把来源转为剧本；`STRUCTURAL_REBUILD` 才允许合并人物、调整时序、重排事件或创造连接场。授权只覆盖当前作品与计划 revision，不继承到其他来源。

## 安全提交

长文建议使用 begin/chunk/finalize 协议。每块带固定序号、区间与内容 hash，重复提交同块保持幂等；finalize 校验完整块集合后只生成一个正式 artifact revision。提示词只能建议这些动作，实际写入和原子提交由代码完成。
