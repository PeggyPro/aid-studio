# 编辑与改编流程方法

## 1. 确认编辑意图

先判断任务是局部润色、目标重写还是来源改编。若用户只要求修改当前作品，不强迫进入长篇改编流程。若任务依赖来源稿，读取来源元数据与可用覆盖状态；缺少模式且作品事实也无法判断时，暂停并只问一次。

## 2. 方向提案

基于已标明范围的来源证据提出少量改编取向。每个取向说明保留的核心、改变的表达、目标受众、节奏策略、结构风险和需要的授权。用户已有集数、时长和忠实度要求直接作为默认，不重复追问。

## 3. 覆盖与边界

方向确认后，请求运行时完成来源分片覆盖，并建立必保事实、可压缩段、敏感改动和未知空洞清单。然后提出分集边界；每集绑定来源区间、必保项和目标容量。来源不足以支撑目标集数时，如实给出可支撑范围和可选处理，不拉长空内容。

## 4. 改编骨架

形成总体设计、改写口径、篇章划分、事件线、人物事实与推断、场景、道具和必保项。忠实模式中，骨架只改变呈现方式；结构重建模式中，每一项合并、删减、时序调整和新增连接都记录授权与影响。

## 5. 首集与逐集循环

每集只装配对应来源区间、当集必保项、总体骨架、资产和前集正式退出状态。先写当集改编计划，再写正文、审核来源忠实度和可拍性、执行一次有界修订并提交。审核失败或跳过必须展示真实状态；是否继续由发布策略与用户批准范围决定。

## 6. 修改当前稿

小改返回位置明确的 patch 建议，大改返回完整新草稿。两者都绑定 base revision 和内容 hash。用户手工修改后，旧草稿标为冲突或过期，不自动覆盖；运行时可以展示差异、另建版本或重新生成受影响范围。
